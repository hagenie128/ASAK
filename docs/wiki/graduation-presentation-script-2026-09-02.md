## 0:30 키오스크 주문 (1분 20초) · 나연

**[SCR-001 홈]**

> 먼저 고객 화면입니다. 매장 식사와 포장 중 하나를 고릅니다.  
> 선택한 **주문 유형**은 장바구니와 결제까지 그대로 유지됩니다.

**[SCR-003 메뉴 → SCR-004 옵션]**

> 메뉴를 고르고 베이스·드레싱·토핑을 선택합니다.  
> 가격은 프론트에서 합산하고, 담기 전에 서버 **장바구니 검증**으로 품절과 필수 옵션을 다시 확인합니다.

**[SCR-005 장바구니 → SCR-007 결제]**

> 장바구니에서 수량을 조정한 뒤 결제로 넘어갑니다.  
> 결제 수단은 **관리자가 켜 둔 수단만** 보입니다.

**[SCR-008 완료]**

> 결제가 끝나면 **주문번호**와 **금액**이 표시됩니다.  
> 서버에는 주문과 결제가 **승인 완료** 상태로 저장됩니다.

> 고객 흐름은 **주문 유형 → 옵션 → 장바구니 → 결제 → 완료**입니다.

**Plan B:** 키오스크 멈추면 사전 녹화 1분 + 「API 연결까지 구현했습니다」

## 1:50 관리자 로그인·주문 (1분) · 하진

**[SCR-015 로그인 — `0001`]**

> 관리자는 매장 번호 **0001**로 로그인합니다.  
> 빈 입력이나 잘못된 번호는 **토스트로 안내**하고, 성공하면 운영 화면으로 들어갑니다.

**[SCR-009 주문 현황]**

> 방금 키오스크 주문이 **접수** 상태로 보이면 **준비 중 → 완료**로 바꿉니다.  
> 목록은 **5초마다 자동 갱신**됩니다. WebSocket이 아니라 **API 재조회** 방식입니다.  
> 완료 처리 시 **음성 안내(TTS)** 로 호출 번호를 읽어 줍니다.

**[SCR-010 주문 관리 — 상세]**

> 주문 관리에서는 목록·필터·상세를 볼 수 있습니다.  
> 고객이 고른 **옵션**과 **빼기 재료**가 구분되어 보여, 주방에서 그대로 확인할 수 있습니다.  
> 결제가 승인된 주문은 주문 현황에서 바로 취소하지 못하고, **주문 관리의 환불**로 처리합니다.

## 2:40 품절·결제수단 (50초) · 하진

**[SCR-011 품절 — 재료 탭]**

> 품절 관리에서 **닭가슴살** 같은 CORE 재료를 품절 처리하면, 카드에 **영향 메뉴 N개**가 표시됩니다.  
> 저장 전에 「변경 내용을 저장할까요?」로 한 번 더 확인합니다.  
> Admin 저장·복구는 **실DB에서 확인했습니다.**

*(가능하면 Kiosk에서 해당 메뉴 SOLD OUT — 안 되면)*  
> 키오스크 반영은 오늘 **시연 목표**이고, Admin 저장은 이미 검증했습니다.

**[SCR-018 결제수단]**

> 결제수단 화면에서 **활성/비활성**과 **노출 순서**를 바꿀 수 있습니다.  
> 저장하면 서버에 반영됩니다. 시연 후에는 **원래대로 되돌립니다.**

> 참고: 결제 **정책 문구** 수정은 이 기기에만 저장되고, 키오스크에는 반영되지 않습니다.

## 3:10 매출 (40초) · 하진

**[SCR-019 매출 요약]**

> 매출 요약에서는 **오늘·이번 주·이번 달** 버튼으로 기간을 바꿀 수 있습니다.  
> 차트는 **해당 달 전체 일자**를 보여 주고, **오늘 이후 날짜**는 비활성입니다.  
> API에 데이터가 없는 날은 시연용 **더미**로 채워 차트가 비지 않게 했습니다.

**[SCR-021 일별 / SCR-020 월별 — 시간 있을 때]**

> 일별 화면에서는 날짜를 고르고 **월 전체 막대**와 시간대별 매출을 볼 수 있습니다.

**(선택) 환불 — 사전 준비 CARD 주문 1건만**

> 환불은 **카드·승인 완료** 주문에 대해 사유를 고른 뒤 실행합니다.  
> 성공 시 주문 **취소**, 결제 **환불**, 매출은 **순매출**로 다시 집계됩니다.  
> 8월 28일 데이터로 **951,100원 − 60,800원 = 890,300원**까지 API로 맞춰 봤습니다.

**Plan B:** 환불 실패 → 9/1 캡처 화면  
**하지 말 것:** 영수증 재출력, KAKAO/NAVER 환불, 환불 두 번 시도

## 3:50 메뉴 (30초, 시간 있을 때) · 하진

**[SCR-016 메뉴 관리]**

> 메뉴 관리에서는 목록·상세·수정이 가능합니다.  
> 재료 추가·제거, **판매 중/품절** 토글, 추천 옵션을 저장하면 **실제 API**로 반영됩니다.  
> 이미지 **파일 선택**은 **미리보기만** 되고, 서버 업로드는 아직 범위 밖입니다 — 그렇게 말씀드리겠습니다.

## 4:20 마무리 (40초) · 공동

> 정리하면, ASAK는 **키오스크 주문 → 관리자 운영 → 품절·결제수단 → 매출**이 하나의 백엔드와 DB로 연결됩니다.

**구현한 것**

- 주문·결제 상태 분리, 가상 카드 승인·환불
- 재료 품절과 **영향 메뉴** 안내
- 매출 요약·일별·월별 집계

**범위 밖 (솔직히)**

- 실제 PG, 실물 프린터, 회원·쿠폰, WebSocket
- 메뉴 이미지 서버 업로드, RTOS는 리허설 성공 시 Q&A만

> 감사합니다. 질문 받겠습니다.

## Q&A 30초 답변

| 질문 | 답변 |
| --- | --- |
| 실제 결제인가요? | 시연용 **가상 카드**입니다. 상태 전이와 매출 집계는 **실DB**로 검증했습니다. |
| WebSocket인가요? | 아닙니다. 관리자 주문 현황은 **5초 폴링**입니다. |
| 품절이 키오스크에도 되나요? | Admin 저장은 확인했습니다. Kiosk는 **CORE 재료** 기준으로 시연합니다. |
| 품절 목록이 왜 적나요? | **CORE·BASE·제거불가** 재료만 탭에 넣었습니다. |
| 환불 후 DB는? | 주문 `CANCELED`, 결제 `REFUNDED`, 매출은 **순매출**로 재집계됩니다. |
| RTOS/프린터? | POSIX **콘솔 시연**까지 구현. 실물 장비는 후속 범위입니다. |
