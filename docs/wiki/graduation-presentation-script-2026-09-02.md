## 슬라이드별 대본 (28장)

### 1~2 · 표지·목차 · 공동 (30초)

> 안녕하세요. 샐러드 키오스크 **ASAK** 프로젝트, **다비치** 팀입니다.
> **React 키오스크**, **React 관리자**, **Spring Boot**, **MySQL**로 주문부터 매출까지 한 흐름을 만들었습니다.
> 오늘은 고객 주문이 관리자 운영·품절·매출까지 **같은 데이터**로 이어지는 것을 보여 드리겠습니다.

### 3~4 · 프로젝트 개요·팀 · 공동 (40초)

> 샐러드는 메뉴 선택 뒤에도 옵션·재료 제외·수량 조절이 이어집니다.
> ASAK는 이 과정을 **단계별 화면**으로 나누어 주문 실수를 줄이는 것을 목표로 했습니다.
> 2인 팀으로 **Kiosk·Admin**을 중심에 두고, API 연동과 통합 테스트까지 맡았습니다.

### 5~6 · 수행 절차·경과 · 공동 (20초, 빠르게)

> 기획·화면 설계 → API·DB → 구현·검증 순으로 진행했습니다.
> 문서와 코드가 어긋나지 않도록 WBS·Bruno·QA로 계속 맞춰 왔습니다.

### 7~8 · 기술 스택·시스템 구조 · 하진 (40초)

> Kiosk·Admin은 **React 19**, 상태는 **Zustand**, API는 **Axios**입니다.
> 백엔드는 **Spring Boot + MyBatis + MySQL**이고, 이미지는 **Cloudinary**를 씁니다.
> 결제 PG는 **미연동**이며, 시연은 **가상 결제**로 진행합니다.
> Admin에서는 실시간 주문·주문 관리·메뉴·품절·매출·결제수단을 한 흐름으로 봅니다.

### 9~10 · ERD · 하진 (30초, 빠르게)

> 메뉴·재료·옵션 구조와 주문·결제·공통코드를 분리해 설계했습니다.
> 품절·매출 집계는 **뷰와 매퍼**로 Admin·Kiosk가 같은 기준을 쓰도록 맞췄습니다.

### 11 · 키오스크 주문 한 줄 지도 · 나연 (20초)

> 키오스크는 **카테고리 → 메뉴 → 옵션 → 장바구니 → 결제** 순입니다.
> 이전 단계로 돌아가도 **선택 값은 유지**됩니다. 이게 Kiosk UX의 핵심입니다.

### 12~13 · 메뉴 목록·상세 · 나연 (슬라이드 20초 → 라이브)

**[슬라이드]**

> 카테고리별 메뉴를 보고, 메뉴명·가격·이미지·품절 상태를 한 화면에서 확인합니다.
> 상세에서는 **필수·선택 옵션**과 **제외 가능 재료**를 정책에 맞게 구분합니다.

**[라이브 SCR-003~004]**

> 매장/포장을 고른 뒤 메뉴를 선택하고, 베이스·드레싱·토핑을 고릅니다.
> 담기 전에 서버 **장바구니 검증**으로 품절과 필수 옵션을 다시 확인합니다.

### 14 · 메뉴·옵션 품절 · 나연 (슬라이드 15초)

> **메뉴 전체 품절**과 **개별 옵션 품절**을 화면에서 구분합니다.
> 메뉴가 품절이면 주문을 막고, 옵션만 품절이면 해당 옵션만 선택할 수 없게 했습니다.

*(라이브에서 SOLD OUT 메뉴·옵션이 보이면 짚어 주기 — **시연 목표**)*

### 15 · 장바구니 · 나연 (라이브 20초)

> 선택한 메뉴·옵션·제외·수량·금액을 확인한 뒤 결제로 넘어갑니다.

### 16 · 결제 프로세스 · 나연 (슬라이드 20초 → 라이브)

**[슬라이드]**

> **주문 확인 → 결제수단 선택 → 결제 진행 → 결제 완료**를 단계별 화면으로 나눴습니다.
> 현재는 **가상 결제 프로세스**입니다.

**[라이브 SCR-007]**

> 관리자가 켜 둔 결제수단만 노출됩니다. *(Admin→Kiosk 반영은 **미검증** — 말할 때 구분)*

### 17 · 예외 상황 · 나연 (슬라이드 15초)

> 타임아웃, 빈 장바구니, 장바구니 비우기, 결제수단 미선택처럼
> **상황별 안내 팝업**으로 다음 행동을 알려 줍니다. 단순 에러 문구가 아닙니다.

*(본편에서 재현 안 해도 됨 — 슬라이드로 설명)*

### 18 · 주문 완료·영수증 · 나연 (슬라이드 15초 → 라이브)

**[슬라이드]**

> RTOS 콘솔 출력까지 연결해 두었고, **리허설 성공 시 Q&A**에서만 시연합니다.

**[라이브 SCR-008]**

## 라이브 시연 · 관리자 (슬라이드 19~22 연계)

### 19 · 관리자 주문 관리 · 하진 (1분)

**[SCR-015 로그인 — `0001`]**

> 관리자는 매장 번호 **0001**로 로그인합니다. 잘못된 번호는 **토스트**로 안내합니다.

**[SCR-009 주문 현황]**

> 방금 키오스크 주문이 **접수**로 보이면 **준비 중 → 완료**로 바꿉니다.
> **5초마다 API 재조회**합니다. WebSocket이 아닙니다.
> 완료 시 **TTS**로 호출 번호를 읽어 줍니다.

**[SCR-010 주문 관리 — 상세]**

> 옵션과 **빼기 재료**가 구분되어 보입니다.
> 승인된 주문은 현황에서 바로 취소하지 못하고, **환불**로 처리합니다.

**[영수증 재출력 — 시간 있을 때]**

> 주문 관리에서 **영수증 출력**을 누르면 RTOS로 텍스트 영수증을 보냅니다.
> 결제수단은 서버 객체(`methodName`)를 **한글 라벨**로 변환해 표시합니다. *(9/2 수정 반영)*

> **하지 말 것:** KAKAO/NAVER 환불, 환불 두 번 시도

### 20 · 관리자 메뉴 관리 · 하진 (30초, 시간 있을 때)

> 메뉴 목록·상세·수정, 재료 추가·제거, **판매 중/품절** 토글을 API로 저장합니다.
> 이미지 **파일 선택**은 **미리보기만** — 서버 업로드는 범위 밖입니다.

### 21 · 관리자 품절 · 하진 (50초)

**[SCR-011 품절]**

> 메뉴·재료 품절을 Admin에서 관리하면 Kiosk 주문 화면에도 같은 기준을 적용합니다.
> 재료 탭에서는 **영향 메뉴 N개**가 표시됩니다.
> Admin 저장·복구는 **실DB에서 확인했습니다.**

*(가능하면 Kiosk에서 해당 메뉴 SOLD OUT — **MENU 단위** 권장)*
> 재료 ing125만으로는 Kiosk 반영이 **FAIL**로 기록되어 있습니다. **메뉴 품절**로 시연하세요.

### 22 · 관리자 매출 · 하진 (40초)

**[SCR-019 매출 요약]**

> **오늘·이번 주·이번 달** 버튼으로 기간을 바꿉니다.
> 차트는 **해당 달 전체 일자**를 보여 주고, KPI·표는 **미래일 제외**합니다. *(9/2 UI 수정)*
> 데이터 없는 날은 시연용 **더미**로 채웁니다.

**(선택) 환불 — 사전 준비 CARD 주문 1건만**

> 환불 성공 시 주문 **취소**, 결제 **환불**, 매출 **순매출** 재집계.
> 8/28 기준 `951,100 − 60,800 = 890,300`까지 API로 맞춰 봤습니다.

**Plan B:** 환불 실패 → 9/1 캡처 화면

### 23~26 · 수행 프로세스·피드백·결과물 · 공동 (40초, 빠르게)

> GitHub·Notion·Figma·Bruno로 협업했고, QA·API 명세·WBS를 함께 갱신했습니다.
> 피드백으로 API 네이밍·전역 상태·품절 뷰 범위를 맞췄습니다.

### 27 · 자체 평가 · 공동 (20초)

> Kiosk·Admin·Backend를 분리 개발하고, 옵션·제외 재료까지 담는 구조를 설계했습니다.
> 화면·API·DB가 각각 정상이어도, **한 주문이 끝까지 같은 데이터**인지 보는 게 통합 테스트의 핵심이었습니다.

### 28 · 마무리 · 공동 (20초)

> ASAK는 **키오스크 주문 → 관리자 운영 → 품절·결제수단 → 매출**이 하나의 백엔드와 DB로 연결됩니다.

**구현한 것**

- 주문·결제 상태 분리, 가상 카드 승인·환불

**범위 밖 (솔직히)**

- 실제 PG, 실물 프린터, 회원·쿠폰, WebSocket
- 메뉴 이미지 서버 업로드, Admin 결제수단 → Kiosk 즉시 반영(미검증)
- RTOS는 리허설 성공 시 Q&A만

## Q&A 30초 답변

| 질문 | 답변 |
| --- | --- |
| 실제 결제인가요? | 시연용 **가상 카드**입니다. 상태 전이와 매출 집계는 **실DB**로 검증했습니다. |
| WebSocket인가요? | 아닙니다. 관리자 주문 현황은 **5초 폴링**입니다. |
| 품절이 키오스크에도 되나요? | **MENU·OPTION**은 API QA **PASS**. **재료 ing125**만 Kiosk **FAIL**. Admin 저장은 확인했습니다. |
| 품절 목록이 왜 적나요? | **CORE·BASE·제거불가** 재료만 탭에 넣었습니다. |
| 영수증 결제수단이 이상했는데? | API가 객체로 내려와 `[object Object]`가 나왔고, **9/2 라벨 변환으로 수정**했습니다. |
| 환불 후 DB는? | 주문 `CANCELED`, 결제 `REFUNDED`, 매출 **순매출** 재집계. |
| RTOS/프린터? | POSIX **콘솔 시연**까지 구현. 실물 장비·영구 큐는 후속 범위. |
| PPT에 간편결제 슬라이드는? | **결제 프로세스(16장)**에 결제수단 선택·진행·완료를 **한 슬라이드**로 합쳤습니다. |
