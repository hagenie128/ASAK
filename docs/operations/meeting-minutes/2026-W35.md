## 확정·합의

| 항목 | 내용 | 상태 |
|---|---|---|
| 결제수단 필드 정본 | API-014·Admin·Kiosk 모두 **`active`** 사용. `boolean isEnabled`는 Lombok+Jackson 직렬화 이슈로 폐기 (W34 결정 유지) | 확정 |
| 결제수단 이미지 | DB `pay_method_cfg.image_asset_id` → **`media_asset` 조인**으로 URL 확보. 명세의 `imageAssetId`만으로는 화면 출력 불가 — asset 테이블 조인이 정본 | 확정 |
| 결제수단 아이콘 UI | 카드·간편결제 로고 등 **기본 UI 아이콘은 `public/` 정적 파일 유지** 가능. Cloudinary 업로드는 메뉴·미디어 중심 | 확정 |
| API-014 명세 갱신 | `description`·`imageAssetId` 컬럼 추가 반영 필요. 나연 담당으로 명세·DTO 정렬 진행 | 진행 |
| DB 컬럼 변경 소통 | **DB·mapper·DTO·명세 변경 시 팀 채널에 즉시 공유**. AI 작업 포함, 사후 알림 없이 컬럼명만 바꾸지 않음 | 확정 |
| 옵션 정리 (W34 후속) | 깨진 빼기 옵션 4개 `opt_policy_item.active=0` 숨김. `remove=1` 재료 빼기 XML 조건 유지 | 진행 |
| 환불 정책 | 가상 CARD 환불 API·Admin UI 연결 착수. 실 PG 환불은 시연 범위 외 | 진행 |
| 키오스크 `.env` | `VITE_API_BASE_URL`, 토스 테스트 키, `VITE_PAYMENT_PUBLIC_ORIGIN` — **별도 문서·채널 공유** (시크릿 본문은 회의록에 미기록) | 확정 |

### 검토했으나 채택하지 않은 안

- 결제수단 응답에 URL만 단독 필드 추가 — asset 정규화 유지, **조인으로 URL 제공**이 정본
- `isEnabled` 복귀 — 프론트 `enabled`/`isEnabled` 혼선 재발 → **`active` 유지**
