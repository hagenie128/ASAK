# ASAK DevCopilot Sync

## 목적

DevCopilot은 ASAK의 보조 협업 도구다. 코드, Product Bible, Screen Bible, 현재 기준 문서가 정본이며 DevCopilot 내용이나 오래된 내보내기로 정본을 덮어쓰지 않는다.

## 시작 전 확인

1. 대상 저장소의 Git 상태와 사용자 승인 범위를 확인한다. 소스 코드, Product Bible, Figma 기준은 명시적인 `코드 수정 승인` 없이는 수정하지 않는다.
2. 현재 세션에 실제 DevCopilot MCP 도구가 있는지 먼저 확인한다. 없으면 `MCP 미지원`으로 기록하고, 사용자가 허용한 REST 또는 브라우저 수단을 별도 표기한다.
3. 작업공간은 기본적으로 `workspace 2`로 하되, URL이나 사용자가 다른 범위를 지정하면 그 범위만 사용한다. 토큰, 쿠키, Authorization 헤더는 파일·커밋·보고서·채팅에 남기지 않는다.
4. 로컬 정본 우선순위를 확인한다: 현재 코드와 검증 결과 → `docs/wiki/current-status-baseline.md` 및 구현 맵 → Product Bible/Screen Bible → DevCopilot → 과거 Notion 내보내기.

## 전수 점검 범위

다음 여덟 종류를 모두 조회하고, 각 항목을 `동기화`, `변경 없음`, `사람 결정 필요`, `MCP 미지원` 중 하나로 분류한다.

| 범위 | 비교 기준 | 주의 사항 |
|---|---|---|
| Wiki | 현재 기준 문서와 정확한 원격 페이지 ID | 제목 검색만으로 새 페이지를 만들지 않는다. |
| 요구사항 | Product Bible 요구사항 ID, 제외 범위 | 상태만 보고 본문을 추정 작성하지 않는다. |
| WBS/작업 | `wbs-v2`의 WBS2 ID와 상태 | `[ARCHIVED DUPLICATE]`, `[SUPERSEDED]`는 보존 레코드다. 정본 WBS와 분리한다. |
| API | 실제 backend 계약·Bruno·API 정본 | 명세만 있고 구현 증거가 없으면 구현 완료로 바꾸지 않는다. |
| 시나리오 | 사용자 시나리오 정본과 Screen ID | 관리자 권한 또는 브라우저 입력 필요 여부를 별도 기록한다. |
| QA | QA Bible, 테스트 케이스, 실행 증거 | 계획과 실행 결과를 혼동하지 않는다. |
| 화면 | Screen Bible, Figma Frame/Node, `screens.json` | SCR ID, 상태, Figma 링크를 함께 확인한다. |
| DB 테이블/뷰 | 실제 DB/DDL/검증된 schema 동기화 기록 | 오래된 스냅샷으로 원격 ERD를 덮어쓰지 않는다. |

## 안전한 동기화 절차

1. 원격 목록·개수·상태와 개별 ID를 읽는다.
2. 각 불일치에 대해 정본 파일, 코드 증거, 원격 ID, 변경 전·후 값을 기록한다.
3. 현재 정본이 명확하고 사용자가 해당 외부 갱신을 승인한 경우에만 **기존 ID 하나씩** 갱신한다.
4. 중복 생성, 삭제, 일괄 초기화, 오래된 `docs/notion` 입력의 전체 덮어쓰기는 사용자가 정확한 대상과 복구 계획을 승인한 경우에만 한다.
5. 갱신 직후 동일 원격 ID를 다시 조회해 제목·상태·본문 반영을 확인한다.
6. 로컬 문서를 갱신했다면 근거와 남은 불일치를 문서에 남긴다. 자동 Git commit, push, merge는 하지 않는다.

## MCP 미지원 또는 불가 항목 보고

MCP가 없거나 특정 필드/관계 변경을 지원하지 않으면, 성공한 것처럼 표현하지 않는다. 아래 형식으로 결과를 제시한다.

| 범위/필드 | 판정 | 근거 | 대안 | 다음 조치 |
|---|---|---|---|---|
| 예: WBS Evidence | MCP 미지원 | 현재 세션 도구 또는 API 스키마에 Evidence 쓰기 없음 | 로컬 `wbs-v2` Evidence 유지 | DevCopilot 기능 제공 시 재점검 |

- REST로 처리했다면 `MCP가 아닌 REST fallback`이라고 명시한다.
- 관리자 로그인·브라우저 조작·권한 승인이 필요한 경우는 사람 수행 항목으로 남긴다.
- 비밀값, 개인 계정, 로그인 세션은 보고서에 넣지 않는다.

### DevProject Hub MCP 3.4.4 확인 기준

현재 확인된 MCP는 요구사항, 시나리오, 화면, WBS, API 명세, DB 테이블·컬럼, QA 테스트케이스, 버그의 조회·생성·수정(버그는 생성·삭제만)을 제공한다. 다음은 별도 분류한다.

| 항목 | MCP 판정 | 처리 원칙 |
|---|---|---|
| Wiki | 미지원 | 정확한 원격 Wiki ID를 확인한 뒤 사용자가 허용한 REST fallback으로만 갱신한다. |
| WBS Evidence/상세 근거 | 미지원 | 로컬 `wbs-v2` Evidence를 정본으로 보존한다. |
| 요구사항·화면·WBS·API·DB·QA 간 관계(link mutation) | 미지원 | 관계를 추정 생성하지 않고 로컬 추적성 문서에 근거를 남긴다. |
| 버그 수정 | 미지원 | 수정이 필요하면 별도 REST/API 지원 여부 또는 사람 조치를 보고한다. |

4. MCP 미지원/불가 항목 표 및 가능한 대안.
