# 퇴근

오늘의 작업을 실제 Git, 코드, 문서, Figma, 테스트 근거와 대조해 워크로그와 필요한 문서에 정확히 남긴다.

구현, 검증, 배포, 다음 할 일을 섞어 쓰지 않는다.

소스코드, DB, Figma 화면, Git 원격 상태는 바꾸지 않는다.

## 허용 변경 범위

이 스킬이 수정할 수 있는 것은 사용자가 승인한 워크로그와 문서뿐이다.

다음은 수행하지 않는다.

- 소스코드 수정
- DB 변경
- Figma Frame/Node 수정
- Git branch, commit, push, merge
- 서브모듈 참조 변경
- 요청받지 않은 WBS 상태 변경
- 요청받지 않은 API 계약 변경
- 요청받지 않은 Product Bible·Screen Bible 변경
- 확인되지 않은 완료 상태 기록

## 사실 종류별 정본 원칙

- 현재 구현 사실: 실제 코드 → 실행·테스트 결과 → Git 이력
- 사용자 경험과 업무 규칙의 의도: Product Bible → Screen Bible → 승인된 결정 기록
- API 계약: 승인된 API 명세와 실제 서버·클라이언트 구현 비교
- 디자인: 승인된 Figma Frame/Node
- DB 반영: 실제 DB 조회 또는 검증된 실행 기록
- 배포 상태: 실제 배포 로그, 원격 상태, 서비스 확인 결과

커밋 존재만으로 기능 검증, DB 반영, 배포 완료를 기록하지 않는다.

## 결과 파일

대상 저장소 또는 팀 문서 저장소에서 기존 워크로그 위치와 작성 규칙을 먼저 찾는다.

기존 규칙이 있으면 그 경로와 형식을 따른다.

기존 규칙이 없으면 다음 경로를 사용한다.

```text
일일 요약: docs/worklogs/YYYY-MM-DD.md
상세 기록: docs/ai-reports/YYYY-MM-DD/asak-signoff-<짧은-주제>.md
```

기존 파일이 있으면 전체 덮어쓰기하지 않는다.

오늘 항목을 기존 구조에 맞춰 추가하거나 갱신하고, 이전 기록을 보존한다.

## 시작 전 확인

1. 날짜, 작성자, 대상 저장소, 기록 범위를 확인한다.
2. `AGENTS.md`, Git 상태, 최근 커밋, 기존 워크로그를 읽는다.
3. 작업과 직접 관련된 Product Bible, Screen Bible, API 문서, Figma를 읽는다.
4. UI가 아닌 작업에 Figma 확인을 형식적으로 강제하지 않는다.
5. ASAK, ASAK-back, ASAK-Admin, ASAK-Kiosk의 변경을 저장소별로 분리한다.
6. 상위 작업공간 저장소와 하위 독립 저장소의 변경을 섞지 않는다.
7. 기존 사용자 변경과 이번 기록 작업의 변경을 구분한다.

## 근거 수집

다음 근거를 실제로 확인한다.

- 변경 파일
- 핵심 함수·데이터 흐름
- 현재 브랜치
- 로컬·원격 커밋
- 원격 반영 여부
- 실행한 테스트·빌드·브라우저 확인
- API 호출 결과
- DB 조회 결과
- 관련 문서 변경
- Figma Screen ID, Frame/Node, 상태별 화면

다음 원칙을 지킨다.

- SQL 정의 수정은 실제 DB 조회 전까지 `DB 반영`으로 적지 않는다.
- GitHub push는 배포 완료의 근거가 아니다.
- Mock 화면 확인은 실제 API 연결의 근거가 아니다.
- API 응답 확인은 DB 전체 정합성 검증의 근거가 아니다.
- 테스트 계획과 실제 테스트 실행 결과를 구분한다.
- 미실행 항목을 성공 또는 통과로 기록하지 않는다.

## UI 근거

UI 관련 작업이면 최신 Figma에서 다음을 확인한다.

- Screen ID
- Frame/Node
- Default
- Loading
- Empty
- Error
- Disabled
- 주요 문구
- 이동 경로
- 데이터 필드

예전 Node를 현재 기준으로 추정해 적지 않는다.

Figma 연결이나 조회 권한이 없으면 `Figma 미확인`으로 기록한다.

## 워크로그 작성 기준

### 일일 워크로그

다음을 간결하게 기록한다.

1. 오늘의 한 줄 요약
2. 직접 수행한 작업
3. 실제 확인한 검증 범위
4. 미검증 항목
5. 다음 작업

### 상세 워크로그

다음을 기록한다.

1. 목적
2. 대상 저장소
3. 변경 파일
4. 커밋과 브랜치
5. 데이터 흐름
6. 실행한 검증
7. AI 또는 도구 도움 범위
8. 이슈와 판단
9. 남은 위험
10. 다음 작업

`AI 또는 도구 도움 범위`에는 사용한 도구와 도움받은 작업 범위만 기록한다.

비공개 추론 과정, 프롬프트 전문, 토큰, 쿠키, 개인정보, 원본 오류 로그 전체를 기록하지 않는다.

## 상태 문서 갱신

WBS, 상태 노트, API 계약, DB 문서는 해당 근거가 상태·계약·운영 판단에 실제로 영향을 줄 때만 갱신한다.

완료 상태는 DoD와 실제 검증 증거가 있을 때만 바꾼다.

다음은 완료로 바꾸지 않는다.

- 코드만 작성됨
- 커밋만 존재함
- Mock 화면만 표시됨
- 테스트 계획만 작성됨
- SQL 파일만 수정됨
- API 명세만 작성됨

## Notion 동기화

Notion 동기화가 요청되었으면 수정 직전에 대상 페이지와 속성을 다시 읽는다.

기존 본문을 보존하고 승인된 항목만 추가하거나 갱신한다.

다음은 기록하지 않는다.

- 미확인 원격 반영
- 미확인 DB 반영
- 실행하지 않은 테스트 통과
- 확인하지 않은 배포 완료
- 추정한 완료율

Notion 연결 또는 쓰기 도구가 없으면 성공한 것처럼 표현하지 않는다.

로컬 워크로그만 작성하고 다음을 보고한다.

```text
Notion 미반영
원인:
필요한 사람 조치:
```

## 검증

1. 수정한 문서를 다시 읽는다.
2. 기존 기록이 보존되었는지 확인한다.
3. 수정한 문서에 대해 `git diff --check`를 실행한다.
4. trailing whitespace를 제거한다.
5. 수정한 상대 링크의 대상 존재 여부를 확인한다.
6. 이번 문서 변경과 기존 사용자 변경을 구분한다.
7. 자동 commit, push, branch 작업을 하지 않는다.
