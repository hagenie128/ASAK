### 주문 상세 금액 근거 표시 — SCR-010 · Figma 0718 화면 `134:10630`, 상세 패널 `150:5418` · `feature`

- **작업 목적:** 메뉴명을 한 줄로만 보여 주던 상세 패널에서 기본 단가, 옵션 추가금, 제외 재료, 메뉴 합계를 분리해 금액의 근거를 확인할 수 있게 한다. 영수증 출력 기능을 구현한 것이 아니라, 이후 SCR-023에서 재사용 가능한 표시 데이터인지 검토하는 범위다.
- **직접 구현:** `OrderDetailPanel.jsx`에 수량 보정, 옵션 행 금액, 메뉴 합계 계산을 추가했다. 옵션은 행별로, 제외 재료는 이름을 쉼표로 연결한 한 줄 텍스트로 표시해 상세 패널의 정보 밀도를 낮췄다. `ordersApi` 등 7개 API 모듈은 `*Api.js` 이름으로 바꾸고 주문 목록·상세 호출 import를 갱신했다.
- **데이터 흐름:** `OrderManagementPreview` → `ordersApi.getOrder(orderId)` → `GET /api/admin/orders/{orderId}` → `OrderDetailResponse.items[]` → 패널의 `unitPrice`, `quantity`, `optionItems`, `excludedIngredients`, `totalAmount` 표시.
- **상태/이슈:** SCR-010이 요구하는 목록 `loading`·`empty`·`error`는 `useOrdersQuery`에 있으나, 상세 조회의 loading/error UI와 실제 주문 데이터 검증은 남아 있다. 승인 결제에서 환불·영수증 버튼이 보일 수 있지만 핸들러는 아직 주석 처리돼 있어 동작 완료로 기록하지 않는다.
- **백엔드 정합:** `docs/view.sql`에서 legacy `REQUEST` 옵션 그룹을 `optionItems`와 옵션 표시 View에서 제외하고, 제외 재료는 `item_exclusion`만 정본으로 사용하도록 정리했다. 같은 “빼기”가 옵션·제외 두 곳에 중복 표시되는 것을 막는 범위다.
- **AI 도움:** AI(Codex). 요청: 금액 계산 기준, 현재 코드·Git 이력·Screen Bible 사이의 차이, 검증 범위를 대조하는 보조. 사람이 남긴 부분: 영수증 기능은 구현 완료가 아니라 데이터 표시 재사용 후보로만 남기고, DTO 차이는 실제 코드 기준으로 재기록했다.
- **검증:** `npm.cmd run lint`는 오류 0건(기존 unused 경고 2건), `npm.cmd run build`는 성공했다. 후속 UI/SQL 변경은 커밋·원격 반영까지 확인했으며, 브라우저의 다중 제외 재료와 실제 DB View 적용은 아직 검증하지 않았다.
