## 오늘 작업

### Notion 감사 원칙과 문서 정합성 점검 — `docs` / `audit`

- **작업 목적:** 정보가 늘어나는 과정에서 AI나 작업자가 문서를 임의로 옮기거나 수정해 정본을 훼손하지 않도록 감사 절차를 정한다.
- **직접 판단:** 감사와 변경을 분리했다. 먼저 즉시 수정하지 않고 문제 목록을 만들며, 실제 row 값·링크·정본 위치를 확인한 뒤 승인받은 범위에서만 수정한다.
- **확인한 위험:** WBS 일정과 API 범위가 서로 다르게 기록될 수 있고, 문서가 존재해도 실제 링크나 DB row가 연결되지 않았을 수 있다.
- **협업 의미:** “문서가 있다”와 “문서가 현재 구현·계획과 연결돼 있다”를 구분해, 팀이 잘못된 문서를 기준으로 작업하는 위험을 줄이고자 했다.

## AI 활용 메모

- AI에게 감사 결과를 바로 수정하게 하지 않고, 문제 목록·근거·영향 범위를 먼저 제시하게 했다.
- 정리 작업과 변경 권한을 분리해, AI가 그럴듯한 문장을 만들더라도 실제 정본과 다르면 반영하지 않는 기준을 세웠다.
