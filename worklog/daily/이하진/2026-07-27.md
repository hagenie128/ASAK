## 오늘 작업

### Admin 운영 조회 API 확장 — SCR-009·010·016 · WBS2-035·036·039·053 · `feature`

- **작업 목적:** Admin의 Live 주문, 메뉴, 주문 관리 화면이 mock이 아닌 실제 조회 API로 전환할 수 있도록 DB 뷰·DTO·Controller·Service·Mapper XML을 연결한다.
- **직접 구현:** `vw_order_live` 기반 활성 주문 조회와 `LiveOrderResponse`/`LiveOrderListResponse`를 추가하고, 메뉴 목록·상세 표시/편집용 DTO와 주문 목록 조회를 보강했다. Admin 프론트에는 메뉴 편집 모델 변환과 메뉴 관리 레이아웃 수정을 반영했다.
- **AI 도움:** 기존 API 응답 envelope·WBS·Git 변경 이력을 대조하는 리뷰 보조로 사용했다. Live 카드의 `menus[]`와 주문 목록/상세의 `items[]`를 억지로 동일 DTO로 합치지 않도록 범위를 유지했다.
- **이슈:** `AdminMenuMapper.xml`의 `menuDetailMap`은 Spring 기동 시 resultMap 요소 순서 문제로 시작을 막을 수 있어 후속 정리가 필요하다.
- **검증:** `gradlew.bat compileJava --no-daemon`과 `git diff --check` 통과 후 `84606f6`까지 main 반영 이력을 확인했다. Live 주문은 실제 DB seed·조회 결과로 확인했으며, 메뉴 Mapper Spring 기동·프론트 통합은 잔여다.
- **포트폴리오 요약:** Admin 운영 화면의 핵심 조회 기능을 실제 DB 뷰·MyBatis DTO·공통 응답 규칙으로 연결할 기반을 만들었다.
