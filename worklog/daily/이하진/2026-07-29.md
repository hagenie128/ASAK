### Live 주문 보드 조회 계약 연결 — SCR-009 · Figma 0718 Default `134:10607` · `feature`

- **작업 목적:** 관리자 Live 주문 보드가 메뉴·옵션·경과 시간을 포함하는 전용 조회 계약을 사용하도록 프론트와 백엔드 경로를 맞춘다.
- **직접 구현:** 백엔드 활성 주문 Bruno 요청을 `01-live-orders.bru`로 바꾸고 Live 조회 Controller·Service 계약을 정리했다. Admin의 `ordersApi.listLiveOrders()`와 `LiveOrderPreview`를 `GET /api/admin/orders/live` 조회 흐름으로 연결했다.
- **AI 도움:** Codex가 Git 커밋·Screen Bible·변경 파일을 대조해 완료 범위와 미검증 범위를 기록용으로 정리했다. 구현 코드의 작성·최종 결정은 팀원이 수행했다.
- **이슈:** 완료·취소 요청 메서드와 가로 스크롤 동작은 TODO로 남아 있으며, 상태 변경 기능 완료로 기록하지 않는다.
- **검증:** 커밋 `952555a`, `96c88de`의 변경 파일과 Screen Bible을 대조했다. Spring 기동, Bruno 실호출, 브라우저 default/loading/empty/error는 실행하지 않았다.
- **포트폴리오 요약:** Live 보드의 목업 조회를 전용 API 계약으로 전환하는 기반을 연결하고, 이후 상태 변경과 화면 검증 범위를 분리했다.

### 메뉴 옵션 그룹 추천 카탈로그 분리 — SCR-016 · Figma 0718 Detail Edit `134:12668` · `feature`

- **작업 목적:** 메뉴 목록의 옵션 그룹을 ID 기준으로 중복 없이 모아 메뉴 수정 UI에서 재사용할 수 있는 카탈로그를 만든다.
- **직접 구현:** `useMenusQuery`에서 `detail.optionGroups`를 순회하는 순수 함수 `getOptionGroupCatalog`를 분리하고, 메뉴 목록에서 파생한 옵션 그룹 목록을 반환하도록 정리했다.
- **AI 도움:** Codex가 변경 전후 코드와 SCR-016의 화면 상태를 검토해 문서화 범위를 정리했다.
- **이슈:** 현재 카탈로그의 원천은 목업 메뉴 목록이며 실제 메뉴 관리 API 저장 계약과의 연동은 이 작업 범위 밖이다.
- **검증:** 커밋 `b3fd9f0`의 변경 파일을 확인했다. 메뉴 추가·수정·저장·오류 상태의 브라우저 검증은 실행하지 않았다.
