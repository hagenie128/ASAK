## 2. 작업 목적

- 개인이 알아낸 내용을 대화에서 소모하지 않고, 팀원이 재사용할 수 있는 Notion 하위 페이지와 Markdown 문서로 남긴다.

## 3. 직접 구현 영역

- Markdown 문서를 Notion 페이지로 올리고, 팀이 따라 할 수 있도록 단계별 추천과 사용 목적을 포함한 가이드 구조를 사용했다.
- 코드 학습 자료를 단순 문법 정리가 아니라 **알고리즘 → 문법 → 실제 프로젝트 코드 → 품질/설계 → 디버깅 → SQL** 순으로 묶어 팀 전반에 재사용 가능한 형태로 정리했다.

## 4. 구현 로직 / 적용한 방식

- 워크로그와 학습 문서를 별개로 두지 않고, 프로젝트 작업 중 생긴 질문·디버깅을 이후 공부 자료로 전환하는 흐름을 만들었다.

## 5. AI 도움 영역

- 사용한 AI 도구: 문서 정리 보조 (도구명 불명 — 대화 기반 기록)
- 요청 내용: 설명 내용을 팀용 학습 문서로 재가공
- 도움 준 내용: 초안 설명
- 그대로 사용한 부분: 없음 — AI 설명을 그대로 보관하지 않음
- 수정해서 사용한 부분: 프로젝트 코드와 연결된 예시·검증 순서를 요구해 팀 학습 문서로 재구성

## 8. 이번 작업에서 배운 점

- 프로젝트 중 발생한 질문과 디버깅을 개인 채팅 기록에 남겨두지 않고, Notion/Markdown 기반의 팀 학습 자산으로 전환하는 습관을 만들기 시작했다.

## 10. 검증 내용
