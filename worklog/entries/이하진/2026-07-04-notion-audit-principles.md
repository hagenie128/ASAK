## 2. 작업 목적

- Notion에 정보가 많아지는 과정에서 AI나 작업자가 페이지를 임의로 고치거나 옮겨 정본을 훼손하지 않도록 감사 절차를 만든다.

## 3. 직접 구현 영역

- Notion 감사에서 **즉시 수정 금지 → 문제 목록 작성 → 실제 row 값/링크 검증 → 수정 범위 승인** 순서를 사용하기로 정했다.
- WBS-025/API-016 사이의 일정·스코프 충돌, DB/링크 전체 검증이 남아 있음을 문제 목록으로 분리했다.
- "문서가 있어 보인다"와 "실제로 연결돼 있다"를 구분하고, DB row·링크·정본 위치를 직접 확인하기 전에는 완료로 올리지 않는 기준을 적용했다.

## 4. 구현 로직 / 적용한 방식

- 감사(audit)와 변경(change)을 분리했다. AI에게 정리와 수정 권한을 동시에 주지 않고, 문제를 먼저 나열하게 한 뒤 실제 값을 사람이 확인하고, 승인된 범위에서만 수정을 반영하는 순서를 사용했다.

## 5. AI 도움 영역

- 사용한 AI 도구: Notion 감사 보조 (도구명 불명 — 대화 기반 기록)
- 요청 내용: Notion 페이지·row·링크의 문제 목록화
- 도움 준 내용: 문제 후보 정리
- 그대로 사용한 부분: 없음 — 감사 결과를 바로 수정에 반영하지 않음
- 수정해서 사용한 부분: AI가 제시한 문제 목록을 실제 row 값·링크와 대조해 검증하기 전까지는 반영하지 않는 절차로 제한

## 8. 이번 작업에서 배운 점

- Notion을 단순 문서 저장소가 아니라 검증 가능한 프로젝트 운영 체계로 다루면서, AI 자동수정의 위험을 줄이기 위한 변경 승인 절차를 설계했다.
- 문서도 코드처럼 변경 전 근거와 검증이 필요하다는 점을 확인했다.
