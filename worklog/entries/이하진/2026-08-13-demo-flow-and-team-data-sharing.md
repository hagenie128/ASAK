## 3. 직접 판단 영역

- 시연 흐름을 `메뉴 → 옵션·제외·수량 → 장바구니 → 주문 → Admin 확인`으로 고정했다. 개별 기술(React 상태 관리, Spring 구조 등)을 따로 설명하는 대신 한 사용자 여정으로 묶었다.
- 화면이 실제로 계약·DB와 연결돼 있다는 것을 보이기 위해 Figma, Screen Bible, ERD, Bruno(API 클라이언트), MySQL 직접 조회를 보조 근거로 함께 쓰기로 했다.
- 주문 생성·결제 승인 E2E, Admin mock 제거는 아직 통합 중이므로 발표 시연 범위에서 "완료"로 올리지 않고 별도로 분리해 두었다.
- Cloudinary·DB 변경처럼 공용 자원을 건드리는 작업은 본인 코드가 맞는지만 확인하고 끝내지 않고, 변경 내용과 영향 범위를 팀에 먼저 공유하기로 합의했다. 8/12 이미지·DB 작업이 이 판단의 계기였다.
